# Food Mood Journal

A web application for tracking food intake and mood after meals. Users can log foods, meals, and wellness scores to discover which foods make them feel their best.

## Description

**Food Mood Journal** connects food logging with how you feel after eating. The idea is simple: record what you ate, rate your mood and energy, and let the app help you spot patterns between diet and well-being.

## Features

- User registration (username, email, password)
- Login and logout via Spring Security form login
- Role-based access (`USER`, `ADMIN`)
- Password hashing (BCrypt)
- Landing, login, and register pages
- Protected home page with user profile view and edit
- Food management (create, edit, delete)
- Meal logging (`Meal`, `MealEntry`)
- Post-meal wellness log (mood score, energy score, notes)
- Statistics and top meals ranking
- Insights recommendations generated by the REST microservice
- Admin user management (toggle status and role)

## Integrations

### Food Mood Insights Service

The main application integrates with the **food-mood-insights-service** REST microservice to generate and manage meal recommendations.

| Detail | Value |
|--------|--------|
| Microservice URL | `http://localhost:8081` (configurable via `insights.service.url`) |
| Client | `InsightsClient` (OpenFeign) |
| Used by | `InsightsService` → `InsightsController`, and after saving a wellness log |

**Flow:**
1. User saves a wellness log for a meal.
2. Main app sends meal macros, mood, energy, and food names to the microservice (`POST /api/v1/users/{userId}/recommendations`).
3. Microservice returns a recommendation.
4. User can list, apply, or dismiss recommendations from `/insights`.

Start the insights service on port **8081** before using Insights features.

## Prerequisites

- **JDK 17+**
- **Maven 3.9+** (or the included `./mvnw` wrapper)
- **MySQL 8+** running on `localhost:3306`
- **food-mood-insights-service** running on `localhost:8081` (for Insights)

## Getting Started

### 1. Database configuration

Edit `src/main/resources/application-dev.properties` (or `application.properties`) and set your MySQL credentials:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/food-mood-journal-app?createDatabaseIfNotExist=true
spring.datasource.username=root
spring.datasource.password=YOUR_PASSWORD
insights.service.url=http://localhost:8081
```

The database is created automatically on first run (`createDatabaseIfNotExist=true`).

Optional Spring profiles are available in `application-dev.properties` and `application-prod.properties`. Activate one with:

```bash
.\mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=dev
```

### 2. Build and run

```bash
# Windows
.\mvnw.cmd spring-boot:run

# Linux / macOS
./mvnw spring-boot:run
```

Alternatively:

```bash
mvn clean package
java -jar target/food-mood-journal-app-0.0.1-SNAPSHOT.jar
```

The application is available at: **http://localhost:8080**

### 3. Tests

```bash
.\mvnw.cmd test
```

## Data Model

```
User
 ├── Food
 └── Meal (aggregate root)
      ├── MealEntry → Food
      └── WellnessLog (OneToOne)
```

**Domain entities** (`User`, `Food`, `Meal`) each have a dedicated JPA repository and service.

**Child entities** (`MealEntry`, `WellnessLog`) belong to the `Meal` aggregate. They are persisted and updated through `MealRepository` and `MealService` via JPA cascade — no separate repository or service.

### Entities

| Entity | Type | Fields |
|--------|------|--------|
| **User** | Domain | `username`, `email`, `password`, `role`, `isActive`, `createdOn`, `updatedOn` |
| **Food** | Domain | `name`, `caloriesPer100g`, `proteinPer100g`, `fatPer100g`, `carbsPer100g`, `owner` |
| **Meal** | Domain | `mealType`, `eatenAt`, `owner`, `entries`, `wellnessLog` |
| **MealEntry** | Child of Meal | `quantityInGrams`, `meal`, `food` |
| **WellnessLog** | Child of Meal | `moodScore`, `energyScore`, `notes`, `createdAt`, `meal` |

### Enums

| Enum | Values |
|------|--------|
| **UserRole** | `USER`, `ADMIN` |
| **MealType** | `BREAKFAST`, `LUNCH`, `DINNER`, `SNACK` |

## Authentication

The application uses **Spring Security** with form-based login (`/login`), session cookies (`JSESSIONID`), and role-based authorization (`USER` / `ADMIN`). User details are loaded by `CustomUserDetailsService` into `AuthenticationMetadata`. Passwords are stored hashed with `BCryptPasswordEncoder`. Domain exceptions are handled by `GlobalExceptionHandler` and displayed on `error.html`. Login and register errors are shown on the form. Access to `/users/**` requires the `ADMIN` role.
